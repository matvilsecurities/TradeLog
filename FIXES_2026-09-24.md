# TradeLog — Account Mapping & Save Fixes

Date: 2026-09-24

## Fixes in this package

### 1. Journal Ledger account switching
The main Journal Ledger previously received `dashboardTrades`, which were already scoped to the Dashboard's selected account. That meant the Ledger's own account selector could not reliably switch to another account.

The Ledger now receives all currently active-account trades and performs its own account filtering.

The Ledger filter now resolves both identifiers:

- `accounts.account_id` ↔ `trades.account_id`
- `accounts.id` ↔ `trades.account_uuid`

This makes the canonical UUID mapping authoritative while retaining compatibility with the legacy/application account ID.

### 2. Manual Trade Save / `capture_status` error
Production `public.trades` currently does not have the Phase 39 live-capture columns. Previously, fetched trades exposed `executionIds: []` to the UI, and editing such a trade caused the save layer to interpret the empty array as live-capture metadata and send `capture_status` to Supabase.

The save layer now sends Phase 39 fields only when actual live-capture metadata exists:

- `captureStatus`
- `liveTradeKey`
- `executionCount > 0`
- non-empty `executionIds`

Normal manual trade creation/editing therefore does not require the live-capture migration.

## 2026-09-24 — Manual trade entry account-context fix

A second account-context bug was identified after the account/ledger mapping fix: when the Dashboard was viewing `PA-APEX-18`, a newly saved manual trade could inherit the separate Account Center `activeAccountId` (for example `APEX-21`).

### Fix
- New manual trades now capture an explicit trade-entry account context when `Add Trade` is opened.
- Journal Ledger's `+ Add Trade` passes its selected account into the entry context.
- Dashboard-specific account selection takes precedence when creating a trade.
- Account Center `activeAccountId` is used only as the fallback when no specific Dashboard/Ledger account is selected.
- New trades now receive both the selected account's `account_id` and canonical `account_uuid`.
- Existing trades retain their persisted account identity when edited.
- Post-trade compliance evaluation is now calculated against the account that actually received the new trade, rather than a potentially unrelated active Account Center account.
- Trade entry modal settings/trade history are scoped to the actual entry account.

This prevents a trade intended for `PA-APEX-18` from being saved under `APEX-21` merely because `APEX-21` remained the Account Center active account.
